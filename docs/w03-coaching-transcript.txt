const getProjectDetails = async (projectId) => {
  const query = `
    SELECT p.project_id, p.organization_id, p.title, p.description, p.location,
           TO_CHAR(p.date, 'YYYY-MM-DD') AS date, o.name AS organization_name

JOSEPH:

```js
app.use((req, res, next) => {
  const error = new Error('Page Not Found');
  error.status = 404;
  next(error);
});

app.use((error, req, res, next) => {
  if (res.headersSent) return next(error);
  const invalidIdentifier = error.code === '22P02';
  const isNotFound = error.status === 404 || invalidIdentifier;
  let status = 500;
  if (isNotFound) status = 404;
  console.error('Request failed:', {
    path: req.path,
    status,
    code: error.code || 'SERVER_ERROR',
    message: error.message,
  });
  let title = 'Service Temporarily Unavailable';
  if (isNotFound) title = 'Page Not Found';
  res.status(status).render(`errors/${status}`, {
    title,
    currentPath: req.path,
    error: error.message,
    stack: error.stack,
  });
});
```

Why does the catch-all middleware appear after all normal routes?

JOSEPH:
Express runs middleware in order. It should create a 404 only after no real route has handled the request, or it would block valid pages.

COACH:
Correct. Why does the catch-all call `next(error)` instead of rendering the 404 template itself?

JOSEPH:
It sends 404s through the same centralized error path as other failures. The global handler then owns status selection, logging, template choice, and response formatting.

COACH:
Exactly. How does Express recognize the second function as error-handling middleware?

JOSEPH:

COACH:
Correct. What is the difference between the 404 and 500 cases here?

JOSEPH:
A 404 means the requested route or resource does not exist, so it is a client-side missing-resource response. A 500 means an unexpected server operation failed, such as a database query or rendering problem.

COACH:
Good. Why does the handler check `res.headersSent`?

JOSEPH:
If a response has already started, trying to render another page could produce a headers-already-sent failure. Passing the error onward lets Express finish handling that situation safely.
