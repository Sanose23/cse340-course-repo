TOPIC 3: SESSIONS AND FLASH MESSAGES

MODEL COACH:
This is actual flash code from src/middleware/flash.js:5-31. How do its different calls store and consume temporary messages?

```js
const flash = (req, res, next) => {
  req.flash = (...args) => {
    const [type, message] = args;
    if (args.length > 2 || (args.length > 0 && !isFlashType(type))) {
      throw new TypeError('Use a valid flash message type.');
    }
    if (args.length === 2) {
      if (typeof message !== 'string') throw new TypeError('Flash messages must be strings.');
      req.session.flash ||= {};
      if (!Object.hasOwn(req.session.flash, type)) req.session.flash[type] = [];
      req.session.flash[type].push(message);
      return;
    }
    if (args.length === 1) {
      const messages = req.session.flash && Object.hasOwn(req.session.flash, type) ? req.session.flash[type] : [];
      if (req.session.flash && Object.hasOwn(req.session.flash, type)) {
        delete req.session.flash[type];
        if (Object.keys(req.session.flash).length === 0) delete req.session.flash;
      }
      return messages;
    }
    const messages = req.session.flash || {};
    if (req.session.flash) delete req.session.flash;
    return messages;
  };
  res.locals.flash = req.flash;
  next();
```

SUGGESTED JOSEPH RESPONSE:
Two arguments add a string to the chosen session message array. One argument retrieves and removes that type. No arguments retrieve and remove every type. The middleware exposes the function to templates without consuming messages itself. The type checks and own-property checks avoid treating unsafe object keys as message storage.

SUGGESTED JOSEPH RESPONSE:
